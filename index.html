VCC 商户 Open API 对接指南

VCC Virtual Card Platform — Merchant HTTP API (/open/v1) · Integration guide

概述 · Overview

本文说明商户服务器如何调用 VCC vcc-open-api 下的开放接口：基础路径为 /open/v1，使用 HTTPS，除健康检查外需携带 AccessKey + HMAC-SHA256 签名，且路径必须在平台白名单内。

This guide describes how your backend calls the VCC vcc-open-api surface: base path /open/v1, HTTPS, AccessKey + HMAC-SHA256 on all routes except health, and paths must match the server allowlist.

统一网关与安全 · Gateway & security

与参考站点「数币收单」类文档不同，VCC Open API 不采用 RSA 加密请求体；载荷为明文 JSON，安全边界由 TLS + HMAC 请求签名 + 商户编码校验 + 路径白名单 共同构成。

Unlike some acquirer-style integrations, VCC does not wrap the body in RSA; JSON is sent in clear over TLS, protected by HMAC signing, merchant code binding, and path allowlists.

HTTP 请求头（受保护路径）· Required headers

Protected routes: all /open/v1/** except GET /open/v1/health.

头名称 Header说明 Description
X-Access-Key-Id商户 AccessKey · Merchant access key id
X-Merchant-Code必填。对外商户编码（与门户一致，如 M 前缀格式）· Must match the merchant bound to the key

Canonical Request · 签名字符串

签名字符串为 四行，以换行符 \n 连接（UTF-8）：

The string to sign is four lines joined by \n (UTF-8):

  1. HTTP 方法大写（如 GET、POST）
  2. Servlet 路径：HttpServletRequest#getServletPath()，例如 /open/v1/wallets
  3. 规范化查询串：参数名按字典序；同名多值按值排序；key=value 以 & 连接；URL 编码规则与 application/x-www-form-urlencoded 一致（空格为 %20）。无查询参数时为完全空字符串。
  4. 请求体原始字节的 SHA-256（小写十六进制）；无 body 时对空字节数组做 SHA-256（注意与空 JSON 对象字节不同）。
X-Vcc-Signature = hex_lower( HMAC_SHA256( UTF8(Secret), UTF8(CanonicalRequest) ) )

Secret 与创建/轮换凭证时获得的明文一致；轮换宽限期内旧 Secret 仍可用于验签（与运营/门户流程一致）。

幂等与限流 · Idempotency & rate limits

主题 Topic说明 Description
幂等 Idempotency 变更类请求须带 Idempotency-Key；首次响应可缓存（Redis；测试环境可能进程内）。vcc.open-api.idempotency.fail-open=false 时 Redis 故障可能返回 503。
全局限流 Global RL 按商户维度；默认窗口与阈值见配置 vcc.open-api.rate-limit；Redis 不可用时是否放行由 fail-open 控制。
调额 PATCH 限频 PATCH .../spending-constraint 有独立窗口 vcc.open-api.spending-patch-rate-limit。

Filter order: signature → rate limit → idempotency → controller.

机器可读 OpenAPI · Machine-readable spec

运行服务后拉取分组 JSON，可导入 Postman / Insomnia 或生成 SDK：

curl -sS "{BASE}/v3/api-docs/open-v1" -o open-v1.json

The open-v1 group is aligned with the runtime allowlist (OpenApiPathAllowlist.pathPatternsForSpringDoc()).

发布到 GitHub Pages · Hosting this site

  1. 将本目录 docs/open-api-integration/ 推送到仓库（可与代码同库）。
  2. 打开 GitHub 仓库 → Settings → Pages。
  3. Build and deployment：Source 选 Deploy from a branch，Branch 选 main（或你的默认分支），文件夹选 /docs。
  4. 若 GitHub 要求站点根目录为 docs/ 下的 index.html：可把本页复制为 docs/index.html，或改用 “GitHub Actions” 部署子目录静态资源。
  5. 更常见做法：在 docs/ 下放 index.html，内嵌跳转：<meta http-equiv="refresh" content="0;url=open-api-integration/">，或将整个站点文件直接放在 docs/ 根下使 https://<user>.github.io/<repo>/ 直接打开对接文档。

发布后地址形如：https://<org>.github.io/<repo>/open-api-integration/（取决于你把 index.html 放在 docs 下的哪一级）。
